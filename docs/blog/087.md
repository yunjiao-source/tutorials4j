# 087-对象存储模块-基于 x-file-storage 构建 Spring Boot 文件存储服务：从设计到实践

本文章代码: [gitee](https://gitee.com/yunjiao-source/tutorials4j) , [gitcode](https://gitcode.com/yun-jiao/tutorials4j) , [github](https://github.com/yunjiao-source/tutorials4j)

## 1. 引言

在现代 Web 应用中，文件存储（图片、文档、视频等）是不可或缺的基础能力。无论是用户头像、业务附件还是内容素材，都需要一个稳定、高效且易于扩展的存储方案。常见的做法是对接对象存储服务（OSS，如阿里云 OSS、腾讯云 COS、七牛云等），但直接调用各厂商 SDK 会导致代码耦合度高、切换成本大。

[`x-file-storage`](https://github.com/dromara/x-file-storage) 是一个优秀的开源框架，它抽象了多种存储平台，提供统一的 API，极大简化了文件存储的开发。然而，它本身不负责元数据的持久化、业务关联和查询等，这些需要开发者自行实现。

本文介绍我们基于 `x-file-storage` 构建的一个 Spring Boot 文件存储功能模块，它集成了元数据管理、上传/下载/查询端点、分片记录、缩略图生成、随机目录分配等能力，并封装为可插拔的 Spring Feature。通过本文，你将了解该模块的设计思路、核心组件及关键实现，并可将其应用到你的项目中。

---

## 2. 整体架构

该模块划分为三个层次：

- **启动层**：通过 `@EnableFileStorageSpringFeature` 注解一键导入自动配置。
- **核心业务层**：提供文件记录、查询、转换、进度监听等服务。
- **接口层**：暴露 RESTful API，支持上传、下载、查询。

模块内部包结构如下：

```
tutorials4j.framework.feature.oss
├── annotation                     // 启用注解
│   └── EnableFileStorageSpringFeature
├── autoconfigure                  // 自动配置
│   └── FileStorageSpringFeatureConfiguration
└── fss                            // 功能实现
    ├── DownloadEndpoint
    ├── UploadEndpoint
    ├── QueryEndpoint
    ├── FileDetailEntity / FilePartDetailEntity
    ├── FileDetailRepository / FilePartDetailRepository
    ├── FileDetailService / FilePartDetailService
    ├── FileDetailQuery / FileDetailSpecification
    ├── FileStorageSpringEntityConvert
    └── SimpleDatabaseFileRecorder
```

依赖关系如下：

- `FileStorageSpringFeatureConfiguration` 通过 `@ComponentScan` 扫描 `fss` 包，并将所有 Bean 注册到 Spring 容器。
- `FileStorageService` 是 `x-file-storage` 的核心服务，由该框架自动配置提供。
- `SimpleDatabaseFileRecorder` 实现了 `x-file-storage` 的 `FileRecorder` 接口，负责将文件信息存入数据库。
- 各 Endpoint 依赖 `FileStorageService` 和 `FileDetailService` 完成业务操作。

## 3. 核心组件详解

### 3.1 自动配置与启用注解

`@EnableFileStorageSpringFeature` 是一个 Import 注解，它导入 `FileStorageSpringFeatureConfiguration`，从而触发组件扫描和 JPA 配置。这样，使用者只需在启动类上标注该注解，即可激活整个文件存储功能，无需手动配置扫描路径。

```java
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Import(FileStorageSpringFeatureConfiguration.class)
public @interface EnableFileStorageSpringFeature {}
```

`FileStorageSpringFeatureConfiguration` 同时配置了 `@ComponentScan`、`@EnableJpaRepositories` 和 `@EntityScan`，确保了所有 Repository、Entity 和 Controller 被正确加载。

### 3.2 实体设计

#### `FileDetailEntity`
对应数据库表 `feat_file_detail`，它存储了文件的所有元数据，包括：

- 基础信息：URL、大小、文件名、原始文件名、扩展名、MIME 类型、存储平台。
- 路径信息：basePath、path。
- 缩略图信息：缩略图 URL、文件名、大小、MIME 类型。
- 业务关联：objectId、objectType（可关联任意业务实体）。
- 扩展信息：metadata、userMetadata、attr、hashInfo 等（均以 JSON 字符串存储）。
- 分片上传相关：uploadId、uploadStatus。

实体继承 `BaseEntity`（提供通用 ID、创建时间等字段），同时额外定义了 `createTime` 字段，便于查询。

#### `FilePartDetailEntity`
用于手动分片上传场景，记录每个分片的平台、上传 ID、ETag、分片编号、大小和哈希信息。它与 `FileDetailEntity` 通过 `uploadId` 关联。

### 3.3 转换器 `FileStorageSpringEntityConvert`

`FileInfo` 和 `FilePartInfo` 是 `x-file-storage` 的核心数据对象，包含丰富的元数据（如 `Map<String, String>` 类型的 metadata、`HashInfo` 等），但这些复杂类型无法直接存入关系型数据库。因此，我们需要将其序列化为 JSON 字符串存储，读取时再反序列化。

`FileStorageSpringEntityConvert` 负责双向转换：

- `convert(FileInfo)` → `FileDetailEntity`：使用 Hutool 的 `BeanUtil` 拷贝基础属性，然后将复杂对象调用 `jacksonRecord.toJson()` 转为 JSON。
- `convert(FileDetailEntity)` → `FileInfo`：反向将 JSON 转为 Map、Dict 或 HashInfo。

这样，数据库仅存储文本，保持了良好的可读性和扩展性。

### 3.4 记录器 `SimpleDatabaseFileRecorder`

`x-file-storage` 要求提供一个 `FileRecorder` 实现，用于在文件上传、更新、删除、分片保存时进行持久化。我们基于 Spring Data JPA 实现了 `SimpleDatabaseFileRecorder`：

- `save(FileInfo)`：将 FileInfo 转为实体并保存，同时将生成的 ID 回填给 FileInfo。
- `update(FileInfo)`：调用 `save` 方法覆盖更新。
- `getByUrl(String)`：根据 URL 查询并转换为 FileInfo。
- `delete(String)`：根据 URL 删除记录。
- `saveFilePart(FilePartInfo)` 和 `deleteFilePartByUploadId(String)`：管理分片记录。

所有写操作均标记了 `@Transactional`，保证了数据一致性。

### 3.5 服务层与查询支持

`FileDetailService` 继承 `BaseService`，提供标准 CRUD，并扩展了一个 `find(FileDetailQuery, Pageable)` 方法，用于动态分页查询。

`FileDetailQuery` 封装了可选查询条件（文件名、平台、对象 ID/类型、创建时间范围），通过 `buildSpecification()` 生成 JPA `Specification`。每个条件由 `FileDetailSpecification` 的静态方法构造，支持模糊查询（`filenameLike`）和精确匹配（`platformEqual` 等）。这种设计使得查询逻辑清晰且易于组合。

### 3.6 控制器端点

模块提供了三个 REST 端点：

- **`UploadEndpoint`**：接收 `MultipartFile`，支持指定平台、对象关联、保存文件名，并根据 `isImageType` 决定是否生成缩略图（200x200）。上传过程中若 `log.debug` 启用，会输出进度日志。
- **`DownloadEndpoint`**：根据文件 ID 下载文件。通过 `preview` 参数控制响应头 `Content-Disposition` 为 `inline`（预览）或 `attachment`（下载）。同时自动设置正确的 `Content-Type`（带 UTF-8 编码）。
- **`QueryEndpoint`**：提供三个接口：
    - `/{id}`：获取单个文件的 `FileInfo`。
    - `/{id}/part`：获取该文件的所有分片信息。
    - `/page`：支持分页查询，返回 `PagedModel<FileInfo>`。

## 4. 关键功能实现解析

### 4.1 文件上传：随机目录与缩略图

上传时，我们利用 `OssProperties` 中的 `RandomFolderOptions` 生成随机目录路径，避免单目录文件过多。`RandomFolderOptions.randomPath("/")` 基于 UUID 生成多级子目录（如 `a1/b2/`），可配置每级字符数和级数。

```java
.setPath(properties.getRandomFolder().randomPath("/"))
```

缩略图生成只需调用 `.thumbnail(Boolean.TRUE.equals(isImageType), th -> th.size(200, 200))`，`x-file-storage` 会自动处理图片缩放并上传，缩略图信息会存入 `FileInfo` 的 `thUrl` 等字段，最终被记录器持久化。

### 4.2 文件下载：区分预览与下载

下载接口通过 `preview` 参数区分行为。响应头设置关键点：

- `Content-Type` 使用从 `FileInfo` 获取的 MIME 类型，并附加 `charset=UTF-8`，确保浏览器正确解码文本文件。
- `Content-Disposition` 根据 `preview` 值设为 `inline` 或 `attachment`，同时通过 `.filename(filename, StandardCharsets.UTF_8)` 正确处理中文文件名。

这种方式使得前端无需额外处理即可实现文件预览或下载。

### 4.3 动态查询：Specification 模式

`FileDetailQuery` 的 `buildSpecification()` 将每个非空条件转换为对应的 `Specification`，最后通过 `reduce(Specification::and)` 组合，返回最终的查询条件。若无任何条件，则返回恒真条件 `cb.conjunction()`。这种模式既简洁又灵活，便于后续增加新查询字段。

### 4.4 元数据持久化策略

将复杂对象（如 Map、Dict、HashInfo）转为 JSON 存储，有几个好处：

- 无需额外建表，降低复杂度。
- 存储结构自由，新增字段无需修改表结构。
- 查询时无需解析，仅在转换为 `FileInfo` 时反序列化。

我们使用 `JacksonRecord` 工具类（封装了 Jackson）完成序列化/反序列化，并提供了类型安全的方法（如 `jsonToMetadata` 返回 `Map<String, String>`）。这种设计平衡了扩展性和易用性。

## 5. 配置与扩展

模块的配置通过 `OssProperties` 集中管理，目前包括：

- `randomFolder`：随机目录生成选项（字符数、级数）。
- `metrics`：预留的监控配置（可扩展埋点）。

使用者可在 `application.yml` 中配置：

```yaml
oss:
  random-folder:
    chars-per-sub-dir: 3
    total-sub-dirs: 2
```

未来可扩展如默认平台、缩略图尺寸等参数。

---

## 6. 总结与展望

本文介绍了一个基于 `x-file-storage` 构建的 Spring Boot 文件存储功能模块。它通过注解驱动、自动配置、实体持久化、RESTful API 等方式，提供了完整的文件管理能力。核心设计要点包括：

- **解耦存储平台**：借助 `x-file-storage` 统一 API，支持多种 OSS。
- **元数据持久化**：使用 JSON 存储复杂对象，保持数据库轻量。
- **记录器模式**：实现 `FileRecorder` 接口，无缝集成框架生命周期。
- **查询灵活性**：利用 Specification 支持动态过滤。
- **用户体验**：支持预览/下载切换、缩略图生成、进度反馈。
