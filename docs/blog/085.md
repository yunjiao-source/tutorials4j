# 085-消息模块-从 SMS 示例看函数式消息编程与 StreamBridge 使用

本文章代码: [gitee](https://gitee.com/yunjiao-source/tutorials4j) , [gitcode](https://gitcode.com/yun-jiao/tutorials4j) , [github](https://github.com/yunjiao-source/tutorials4j)

## 1. 函数式编程模型（Functional Programming Model）
Spring Cloud Stream 从 3.x 开始推荐使用 `java.util.function` 接口替代 `@StreamListener`。本例中：
- **Consumer**：`SmsConsumer` 类中的 `sms()` 方法返回 `Consumer<SmsMessage>`，它作为消息处理器。当消息到达输入通道时，该函数被调用。
- 函数名 `sms` 在配置中通过 `spring.cloud.function.definition` 声明，并自动绑定到 `sms-in-0` 输入通道（因为 Spring Cloud Stream 会为每个函数创建输入和输出通道，命名规则是 `{functionName}-in-{index}` 和 `{functionName}-out-{index}`）。

这种方式的优点：
- 业务逻辑纯粹是函数，易于单元测试（直接调用 `accept` 方法）。
- 支持多种消息处理模式（如 `Function` 用于转换，`Supplier` 用于生产）。
- 与 Project Reactor 结合支持响应式流。

## 2. StreamBridge：灵活的消息发送
传统上使用 `@EnableBinding` + `MessageChannel` 发送消息，但新版本推荐使用 `StreamBridge`：
```java
streamBridge.send("sms-out-0", sms);
```
`StreamBridge` 是一个轻量级发送工具，允许动态指定目标通道名称（甚至可包含 binder 信息）。它的优点：
- 无需显式声明 `@Output` 通道。
- 支持运行时决定发送到哪个 destination（通过 `send` 方法的 `String bindingName` 参数）。
- 可以同步或异步发送（默认同步），返回 `boolean` 表示是否发送成功。

## 3. 消息序列化与反序列化
- 生产端：`SmsMessage` 对象通过默认的 `JsonMessageConverter` 转换为 JSON 字符串，`content-type: application/json` 指示了序列化格式。
- 消费端：接收到的 JSON 会自动反序列化为 `SmsMessage`，因为函数签名是 `Consumer<SmsMessage>`，框架会根据 `content-type` 选择对应的转换器。
- 如果希望自定义，可以配置 `spring.cloud.stream.default.content-type` 或针对特定通道设置。

## 4. 错误处理与重试
消费函数内部如果抛出异常，Spring Cloud Stream 默认会重试（默认 3 次），然后记录错误。可以配置：
```yaml
spring.cloud.stream.bindings.sms-in-0.consumer:
  max-attempts: 3
  back-off-initial-interval: 1000
  back-off-multiplier: 2.0
```
或者使用 `@Retryable` 注解（需配合 Spring Retry）。在生产中，建议将失败消息转发到 DLQ（死信队列），在配置中启用：
```yaml
spring.cloud.stream.bindings.sms-in-0.consumer:
  enable-dlq: true
  dlq-name: sms-dlq
```
不同 Binder 的 DLQ 实现不同，但配置方式统一。

## 5. 改进建议
- **手机号生成**：当前用 `AtomicLong` 从 13000000000 开始自增，可能超出手机号范围，可以改用随机数或 UUID。
- **响应返回**：`send()` 方法返回字符串，但缺少对发送结果的判断（`streamBridge.send` 返回 boolean）。可以改为返回成功/失败状态码。
- **日志级别**：已配置 `tutorials4j: TRACE` 便于调试。

## 6. 测试策略
- 单元测试：直接测试 `SmsConsumer` 的 `sms()` 函数，传入 `SmsMessage` 并验证日志输出。
- 集成测试：使用 `@SpringBootTest` + `TestBinder` 模拟中间件，验证完整链路。
- 性能测试：使用 JMeter 压测 `/send` 接口，观察吞吐量，并可对比不同中间件的性能。

## 7. 总结
该示例代码简洁、可扩展性强，展示了 Spring Cloud Stream 在现代微服务中的优雅用法。函数式编程与 `StreamBridge` 降低了学习成本，而 Profile 切换使得环境迁移轻而易举。开发者可以在此基础上快速构建事件驱动的应用。
