请求体缓存实验

演示 CachedBodyHttpServletRequest 多次读取请求体能力 VS 原生请求读取限制

Thymeleaf Bootstrap5 + jQuery
机制说明

Spring 中 HttpServletRequest#getReader() 默认只能读取一次，再次调用会抛出 IOException: Stream closed。
✔ 缓存请求体方案：通过 CachedBodyFilter 将原始请求体包装成 CachedBodyHttpServletRequest，将内容缓存到内存，支持无限次重复读取。
✘ 普通请求：未经过滤器包装时，第二次读取就会失败。

接口端点
  • POST /cached-body/cached 已包装 → 返回 firstRead, secondRead, equals, isRequestWrapped
  • POST /cached-body/non-cached 原生请求 → 第二次读取抛出 Stream closed 异常 (HTTP 500)
下方输入任意文本/JSON/XML，体验缓存与非缓存的差异
请求体内容 (将作为 POST Body 发送，纯文本/JSON均可)
支持中文、特殊符号

经过 CachedBodyFilter 包装 → 支持多次调用 request.getReader()
后端会返回第一次读取、第二次读取以及两者是否相等。

📌 观察重点
- 缓存端点 返回的 isRequestWrapped 应为 true ，且 firstRead 与 secondRead 完全一致，equals = true。
- 非缓存端点 由于第二次读取流已关闭，后端直接抛出异常，前端会收到 HTTP 500，错误消息中包含 “Stream closed” ，证明原生请求无法重复读取。
