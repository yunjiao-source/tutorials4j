基于 Spring Cache | Redis (分布式) + Caffeine (本地) | 多租户隔离示例

💡 缓存验证说明： 对同一ID重复请求，若第二次及之后返回的数据与第一次完全一致（随机字符串/日期不变），则证明缓存生效。
后端控制台会打印首次“数据库中获取数据...”日志，后续请求不再输出。切换不同ID则会重新获取。

🧩 多租户隔离演示 (Redis Tenant)  DEMO租户上下文
调用 /redis/cacheable/tenant-users 接口
📌 租户隔离机制：
接口内部设置 TenantContextHolder.set("DEMO")，缓存Key通常结合租户ID生成。
对比普通Redis users（默认租户），相同业务ID可能返回不同缓存数据 → 租户隔离演示。

🧪 对比测试建议：
  1. 先使用普通Redis模块获取用户ID=1001 → 记录结果A
  2. 再使用租户模块获取相同ID=1001 → 得到结果B
  3. 若A ≠ B，说明租户隔离生效（缓存Key包含租户信息）
  4. 同一租户内再次请求ID=1001，结果应保持不变（租户缓存命中）
💡 缓存命中观察点：
  • Redis/Caffeine模块重复相同ID，响应内容不变
  • 修改ID为新值，内容会刷新（数据库取数）
  • 汽车对象中的Date字段也会被缓存，多次调用时间相同
